# Brookline High School Innovation Fund Website Architecture

## Project Overview

Custom website for the Brookline High School Innovation Fund (BHSIF).

Primary goals:

- Communicate the organization's mission and impact
- Promote events and fundraising efforts
- Showcase funded programs
- Highlight educators and student innovation
- Publish organization-authored stories and updates

The site should be maintainable by non-technical staff while preserving design consistency and content quality.

---

# Technology Stack

## Platform

- WordPress (traditional, not headless)

## Theme

- Fully custom theme
- No page builders
- No Elementor/Divi-style editing experience

## Frontend Tooling

- Vite
- pnpm
- Structured CSS architecture
- Minimal JavaScript

## Custom Fields

- Secure Custom Fields (SCF)
- SCF JSON sync committed to the repository

---

# Editorial Philosophy

The site uses a structured CMS approach.

Editors manage content.

The theme controls:

- Layout
- Design
- Semantic structure
- Accessibility

Editors should not be responsible for visual layout decisions.

---

## WordPress Shell Templates

# Content Model

## Pages

Purpose:

- Mission
- About
- Donate
- Contact
- Landing pages

Editing model:

- SCF Flexible Content
- Structured sections only

Gutenberg is disabled for Pages.

---

## Programs

Custom Post Type

Represents funded initiatives and projects.

Examples:

- Journalism Lab
- Robotics Initiative
- Innovation Showcase

Programs have dedicated pages.

---

## Educators

Custom Post Type

Represents faculty members involved with programs.

Educators have dedicated profile pages.

Educators are intentionally lightweight content entities.

Core information:

- Name
- Department
- Biography
- Photo

Most value comes from relationships to other content.

---

## Events

Custom Post Type

Represents fundraising events, showcases, and community gatherings.

Events have dedicated pages.

---

## Posts

Standard WordPress Posts

Represents organization-authored content:

- Program Spotlights
- Event Recaps
- Announcements
- Newsletter Stories
- Student Success Stories

Gutenberg remains enabled for Posts.

Posts use relationship fields to connect to Programs, Educators, and Events.

---

# Relationships

Programs ↔ Educators

Bidirectional relationship.

A Program may have multiple Educators.

An Educator may participate in multiple Programs.

---

Posts → Programs

Posts may reference one or more Programs.

---

Posts → Educators

Posts may reference one or more Educators.

---

Posts → Events

Posts may reference one or more Events.

---

# Press Coverage

External press coverage is not a content type.

Instead, press coverage is stored as metadata on Programs and Events.

Each press item contains:

- Title
- Publication
- Date
- URL
- Optional image
- Optional summary

Reasons:

- Only 5–10 items per year
- No standalone archive required
- Avoids duplicating third-party content
- Preserves attribution to original publisher

---

# Flexible Content Strategy

Flexible Content layouts are grouped conceptually using semantic prefixes.

Examples:

Title · Hero Standard
Title · Hero Homepage

Content · Rich Text
Content · Text + Image
Content · Quote

Dynamic · Featured Programs
Dynamic · Upcoming Events

Promotion · CTA Banner

Layout names should reflect editorial intent, not visual implementation.

---

# Heading Strategy

Semantic heading levels are owned by templates and sections.

Editors do not select heading levels.

Examples:

- Hero sections render H1
- Major sections render H2
- Cards render H3

The system controls document structure.

---

# Future Direction

Likely future enhancements:

- Related Stories components
- Related Programs components
- News archive
- Program archive
- Event archive
- Organization-wide social media settings

Architecture should continue favoring structured content relationships over freeform tagging.
